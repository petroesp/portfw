# portfw
Консольная утилита для управления DNAT-пробросами портов на Linux-шлюзе (Debian/Ubuntu), стоящем между интернетом и удалёнными устройствами, подключёнными через WireGuard.
# Port Forward Manager

Консольная утилита для управления DNAT-пробросами портов на Linux-шлюзе
(Debian/Ubuntu), стоящем между интернетом и удалёнными устройствами,
подключёнными через WireGuard.

## 1. Назначение

Утилита решает одну конкретную задачу: у вас есть VPS/сервер с "белым" IP,
и вы хотите, чтобы разные внешние порты этого IP перенаправлялись на разные
устройства внутри вашей WireGuard-сети — без ручного набора `iptables`/`nft`
команд и без риска забыть какое-то из необходимых правил (DNAT, FORWARD,
MASQUERADE, hairpin NAT).

## 2. Схема работы

```
Internet
   |
Public IP VPS               1.2.3.4
   |
Linux Server (шлюз)         <- Port Forward Manager
   |
WireGuard VPN                wg0: 10.6.66.0/24
   |
Удалённые устройства         10.6.66.5, 10.6.66.20, 10.6.66.30 ...
```

Примеры пробросов:

| Внешний адрес     | Внутренний адрес     | Протокол |
|--------------------|-----------------------|----------|
| 1.2.3.4:25565      | 10.6.66.20:25565      | TCP      |
| 1.2.3.4:8080       | 10.6.66.30:80         | TCP      |
| 1.2.3.4:22         | 10.6.66.5:22           | TCP      |

Для каждого проброса утилита автоматически создаёт полный набор правил:

1. **DNAT** (PREROUTING) — подмена адреса назначения входящего пакета.
2. **FORWARD** — разрешение прохождения пакета между внешним и WireGuard
   интерфейсом (плюс общее правило `ESTABLISHED,RELATED` для обратного трафика).
3. **MASQUERADE** (POSTROUTING) — подмена адреса источника для исходящего
   трафика через внешний интерфейс (нужно для ответа устройства обратно).
4. **Hairpin NAT** — отдельное MASQUERADE-правило для случая, когда клиент
   *внутри* WireGuard-сети обращается на публичный IP сервера, который
   пробрасывается на другое устройство той же сети.

Внешний и внутренний интерфейсы **никогда не задаются вручную** — они
определяются автоматически:

- внешний интерфейс — по маршруту по умолчанию (`ip route show default`);
- внутренний интерфейс назначения — по фактическому маршруту до IP устройства
  (`ip route get <ip>`), что позволяет работать с любым названием интерфейса
  WireGuard (`wg0`, `wg1`, `wgvpn`, и т.д.) без какой-либо конфигурации.

## 3. Firewall backend

Утилита поддерживает оба стека и выбирает автоматически:

```
если доступен nftables (бинарь nft + рабочая подсистема):
    использовать nftables (создаёт свою таблицу `inet portfw`)
иначе:
    использовать iptables (использует стандартные chains
    nat/PREROUTING, nat/POSTROUTING, filter/FORWARD)
```

Правила помечаются машиночитаемым комментарием вида:

```
portfw:<proto>:<extport>:<dstip>:<dstport>:<role>
```

где `role` — `dnat`, `fwd`, `hairpin`, `established` или `masq`. Благодаря
этому **отдельный конфигурационный файл не нужен** — единственным источником
истины являются сами правила ядра, которые в любой момент можно посмотреть
командами `iptables-save` или `nft list ruleset`.

## 4. Установка

```bash
git clone https://github.com/petroesp/portfw.git
cd portfw
sudo ./install.sh
```

Скрипт установки:

- копирует файлы в `/opt/portfw`;
- создаёт симлинк `/usr/local/bin/portfw`;
- создаёт `/var/log/portfw.log` и `/var/backups/portfw/`.

### Зависимости

Обязательные: `bash` (4.3+), `iproute2` (`ip`), `procps` (`sysctl`), и один
из `iptables` / `nftables`.

Рекомендуемые (для полной функциональности диагностики/проверок):

```bash
apt update
apt install -y wireguard-tools netcat-openbsd curl iputils-ping iptables-persistent
```

- `wireguard-tools` — для модуля проверки WireGuard (пункт меню 6).
- `netcat-openbsd`, `curl`, `iputils-ping` — для автоматической проверки
  доступности после создания правила (пункт меню 9 и автопроверка при
  добавлении).
- `iptables-persistent` (`netfilter-persistent`) — чтобы правила iptables
  переживали перезагрузку при сохранении (пункт меню 10). Для nftables
  используется штатный сервис `nftables.service` и файл `/etc/nftables.conf`.

## 5. Использование

Запуск (обязательно от root — нужны права на iptables/nft/sysctl):

```bash
sudo portfw
```

Появится главное меню:

```
====================================
 Port Forward Manager
====================================
1.  Добавить проброс
2.  Удалить проброс
3.  Изменить проброс
4.  Показать активные правила

5.  Диагностика системы
6.  Проверка WireGuard
7.  Проверка Firewall
8.  Проверка маршрутов
9.  Проверка доступности

10. Сохранить правила
11. Резервная копия
12. Восстановление

13. Показать журнал
14. Экспорт диагностики в файл

0.  Выход
```

### 5.1 Описание пунктов меню

1. **Добавить проброс** — пошаговый мастер: протокол (`tcp`/`udp`/`both`),
   внешний порт (число или диапазон `5000-5100`), IP устройства внутри
   WireGuard, порт назначения. Утилита проверяет конфликты портов, создаёт
   полный набор правил (DNAT/FORWARD/MASQUERADE/hairpin), включает
   `ip_forward` при необходимости и сразу проверяет доступность результата.
2. **Удалить проброс** — показывает список активных пробросов, удаляет
   выбранный (весь набор правил).
3. **Изменить проброс** — удаляет старое правило и создаёт новое с новыми
   параметрами (порт/IP/порт назначения).
4. **Показать активные правила** — таблица всех правил с распознанным именем
   сервиса и счётчиками пакетов/байт.
5. **Диагностика системы** — см. раздел 6.
6. **Проверка WireGuard** — см. раздел 7.
7. **Проверка Firewall** — сырой вывод текущих chain'ов (FORWARD, NAT) для
   активного backend'а.
8. **Проверка маршрутов** — таблица маршрутизации + маршруты до всех
   известных WireGuard-клиентов.
9. **Проверка доступности** — ручная проверка `route` / `ping` / `nc` / `curl`
   до произвольного IP:порта.
10. **Сохранить правила** — сохраняет текущий ruleset штатными средствами
    (`netfilter-persistent save` / `/etc/iptables/rules.v4` для iptables,
    `/etc/nftables.conf` для nftables), чтобы он пережил перезагрузку.
11. **Резервная копия** — `iptables-save`/`nft list ruleset` в
    `/var/backups/portfw/`.
12. **Восстановление** — выбор и восстановление одной из резервных копий.
13. **Показать журнал** — последние 50 строк `/var/log/portfw.log`.
14. **Экспорт диагностики в файл** — полный снимок состояния системы в
    `/root/portfw-diag-<дата>.txt` (для отправки в поддержку/себе на память).

### 5.2 Примеры пробросов

**Minecraft-сервер:**

```
Протокол: tcp
Внешний порт: 25565
IP устройства: 10.6.66.20
Порт назначения: 25565
```

**Веб-сервис на нестандартном порту:**

```
Протокол: tcp
Внешний порт: 8080
IP устройства: 10.6.66.30
Порт назначения: 80
```

**SSH:**

```
Протокол: tcp
Внешний порт: 22
IP устройства: 10.6.66.5
Порт назначения: 22
```

**Диапазон портов (например, для торрент-клиента):**

```
Протокол: both
Внешний порт: 51000-51010
IP устройства: 10.6.66.40
Порт назначения: 51000-51010
```

## 6. Диагностика

Пункт меню 5 запускает полный прогон проверок:

- `net.ipv4.ip_forward` — включён ли форвардинг пакетов;
- `rp_filter` — не находится ли в строгом (`1`) режиме, из-за которого
  теряется асимметричный трафик через WireGuard;
- наличие правил FORWARD/NAT, созданных утилитой;
- работоспособность conntrack (`/proc/net/nf_conntrack` или модуль ядра);
- наличие и состояние WireGuard-интерфейсов;
- состояние сетевых интерфейсов (UP/DOWN) и наличие маршрута по умолчанию;
- наличие Docker (может создавать собственные iptables-правила и
  конфликтовать с ручными FORWARD/NAT);
- наличие и активность UFW;
- наличие и активность firewalld.

При обнаружении устранимой проблемы (например, выключенный `ip_forward` или
строгий `rp_filter`) утилита выводит причину и предлагает исправление:

```
IP Forward выключен.
Исправить автоматически? [Y/N]
```

Docker/UFW/firewalld не исправляются автоматически (это осознанные решения
администратора), но о потенциальном конфликте выдаётся предупреждение.

## 7. Модуль WireGuard

Пункт меню 6:

- находит все активные интерфейсы WireGuard (`wg show interfaces`);
- для каждого — проверяет, поднят ли интерфейс, и выводит его подсеть;
- показывает таблицу пиров: публичный ключ, endpoint, allowed-ips, и время
  с последнего handshake (с подсветкой "активен" / "давно" / "нет
  handshake");
- проверяет наличие маршрута до IP каждого пира.

## 8. Восстановление после перезагрузки

По умолчанию правила iptables/nftables живут только в памяти ядра и
**пропадают при перезагрузке**, если их явно не сохранить:

- **iptables**: пункт меню 10 вызывает `netfilter-persistent save` (если
  установлен пакет `iptables-persistent`) либо пишет в
  `/etc/iptables/rules.v4`. Убедитесь, что сервис `netfilter-persistent`
  включён (`systemctl enable netfilter-persistent`), чтобы правила
  подхватывались при старте.
- **nftables**: пункт меню 10 пишет полный ruleset в `/etc/nftables.conf` и
  проверяет, включён ли `nftables.service` (`systemctl enable nftables`).

Также рекомендуется дополнительно снимать резервную копию (пункт 11) перед
серьёзными изменениями — она не заменяет автозагрузку, но позволяет быстро
откатиться.

## 9. Устранение проблем

| Симптом                                   | Возможная причина                          | Что делать |
|--------------------------------------------|---------------------------------------------|------------|
| Проброс не работает, снаружи порт закрыт   | `ip_forward` выключен                        | Меню 5 → автоисправление |
| Работает снаружи, но не работает изнутри WireGuard-сети (обращение на публичный IP) | Не сработал hairpin NAT / нет маршрута до себя | Меню 8, проверить `ip route get <public_ip>` с самого шлюза |
| Проброс то работает, то нет (асимметричные маршруты) | `rp_filter` в строгом режиме             | Меню 5 → автоисправление |
| Правила пропали после перезагрузки          | Правила не были сохранены                    | Меню 10, установить `iptables-persistent` / включить `nftables.service` |
| DNAT есть, но пакеты не доходят до устройства | Нет маршрута до IP устройства через WireGuard | Меню 8, проверить, что WireGuard peer поднят и `AllowedIPs` включает нужный IP |
| Docker "перебивает" правила                 | Docker создаёт собственные iptables-цепочки  | Меню 5 покажет предупреждение; проверьте порядок правил в `iptables -L -n --line-numbers` |
| UFW/firewalld блокирует трафик              | Активен сторонний firewall-менеджер          | Меню 5 покажет предупреждение; либо настройте исключения в UFW/firewalld, либо отключите его и используйте только Port Forward Manager |

## 10. Дополнительные возможности

- **Автоматическое обнаружение конфликтов портов** — при добавлении проброса
  утилита проверяет, не занят ли уже данный внешний порт/протокол другим
  правилом, и предупреждает до создания дубликата.
- **Счётчики трафика** — пункт меню 4 показывает количество пакетов и байт,
  прошедших через каждое правило (данные берутся напрямую из
  `iptables-save -c` / `nft -a list ...`).
- **Автоопределение имени сервиса по порту** — использует `/etc/services`
  (через `getent services`) плюс небольшой встроенный словарь популярных
  игровых/сервисных портов (Minecraft, WireGuard, RDP, Steam и т.д.).
- **Экспорт диагностики в файл** — пункт меню 14 сохраняет полный снимок
  состояния (sysctl, интерфейсы, маршруты, правила, WireGuard) в
  `/root/portfw-diag-<дата>.txt`.

## 12. Ограничения

- Поддерживается только IPv4 (по требованиям проекта).
- Диапазоны портов поддерживаются только с совпадающим размером диапазона
  на внешней и внутренней стороне (например, `5000-5100 -> 5000-5100`);
  проброс диапазона на другой диапазон другого размера не поддерживается
  штатными средствами DNAT и намеренно не реализован.
- Удаление/изменение правил полагается на то, что внешний интерфейс и
  интерфейс маршрута до устройства не изменились с момента создания
  правила (в норме это так, поскольку оба определяются автоматически и
  стабильно на одном и том же сервере).
